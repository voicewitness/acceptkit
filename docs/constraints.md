# 模块约束

每条约束都对应一类真实发生过的误判或事故。改代码时不能弱化它们。

## 内核

1. **内核零领域知识**：不出现具体 App 名、进程名、包名、设备号、租户号、内部工具名。领域内容只能来自项目配置和 `pack.mjs`。
2. **工具层不调模型**。
3. **未知参数一律拒绝**：静默忽略未知参数会让「我以为改了」和「真的改了」看起来一样。
4. **没有静默缺省**：例如用例没写平台，不能默认按 iOS 处理；必须报错。

## 用例

5. 用例 = 操作树 + 节点断言；断言必须有 `id` 与人话 `assert`。
6. `platform` 必填，只能是 `ios | android | both | web`；宿主写在 `host`。
7. 用例在某平台**可执行**，当且仅当它声明了该平台，且用到的每个操作在操作库里有该平台的配方——后者由机器计算。
8. 断言的适用版本范围（`applies`）是用例资产自己的属性，子节点继承；结论与包版本矛盾时拒绝写入。
9. 标题里说出口的主张（`claims`）必须落到断言上。
10. 新建用例前先查重。

## 运行与证据

11. 运行目录只能由 CLI 创建。
12. 每一步操作都要有过程证据；结果性证据走 `observe`：工具执行、原文落盘、按谓词判。
13. `record` 时校验：证据存在、`--quote` 的片段能在证据原文里找到。
14. 每份证据都有复核状态；驳回即把断言退回待执行。有证据就复核，不等收口。
14a. **装置故障与被测物的失败分开**：命中装置故障形状（超时 / 目标进程不在 / 设备不唯一 / 找不到符号 /
   抓到上一轮的日志 / 落了空文件 / 装不稳）的说法，写入前必须显式归类；归给装置的不许记 `fail`
   —— 装置坏了意味着被测物压根没被证伪过。
14b. **装置故障必须显形，但不计缺口、不改判定**：报告单列「本轮装置故障」。
   一旦它会压低结论，隐瞒它就有了收益；它的用处是给报告的可信度标价、给基建出清单。
14c. **读数要能看出是读出来的**：探针打印「表达式原样 → 它的值」。
   把具名读数写成字面量的脚本不收（`--allow-literal` 要写明为什么它不是读数），
   因为盲审只看得到证据里的结论值，看不到产出它的那段代码。
15. 文字渲染的卡片不算图像证据；图像证据必须是真实的画面截图。
16. 截图前检查画面是否被弹窗遮挡；无法确认时如实记录。

## 流程

17. 需求的评审单批准之前，不允许为它运行用例。批准后改用例，评审单版本 +1 并清空批准状态。
18. 阻塞当场登记；有未上报的阻塞时报告出不来。
19. 报告只讲「过」和「不过」：还有待执行的断言时，报告拒绝生成。
20. 回归轮按评审单点名的全部用例各建一轮。

## 安全

21. **白名单闸门缺省拒绝**：识别不出目标 = 不放行；白名单外 = 不放行。
22. 动作打在某台设备上，必须由本次运行占用这台设备（租约 + 心跳）。
22a. **设备以稳定身份为键，不以通信地址为键**：Android 模拟器的 adb serial 里那个端口按启动顺序分配，会在重启后指向另一台机器；身份是 AVD 名。白名单、租约、run 绑定、证据出处都用身份。
22b. **一次运行只绑一台设备**：claim 之后的观测、截图、装包、项目 ops，目标与 run 绑定的设备不一致就拒绝执行，而不是「以实际跑的为准」。
22c. **设备状态必须观测得到才能叫空闲**：连接 · 开机完成 · 身份反解 · 被测 app 进程 · 租约，五问缺一记「不确定」。某平台答不出来时，这个缺口本身就是要报出来的结论。
22d. **选设备的顺序是复用 → 启动 → 新建**，每一步的候选与淘汰原因写进运行记录；新建必须附「现有的为什么都不行」。
22e. **设备能力要可声明、可过滤**：白名单每台写能力（内存 / GPU / 宿主包 / 登录态），用例声明需求。表达不出「这台跑不了这个用例」，换机的决定就无法复核。
23. 卸载只有用例断言明确要求且用户单独批准才能执行。
24. 危险动作（安装、清数据、发布、删除、任何「会清空」的确认）执行前必须由用户确认。
25. Agent 默认不能替用户批准；用户明确授权执行者批准评审单时，记录实际执行者、授权用户及原话、适用范围与本次理由。其他批准仍保存用户原话。
26. `#secret` 的值不出现在证据、报告、日志里。
27. 用接口直接构造请求不算验收：界面能不能产出那个请求才是最容易出错的环节。接口只用来回读结果。
28. 浏览器自动化使用独立的用户目录和调试端口，不碰用户日常浏览器。

## 开源边界

29. 仓库内不得出现任何内部信息：公司与产品名、内部工具名、内部域名、租户号、设备号、人名、本机绝对路径。由 `scripts/leakscan.mjs` 检查：通用规则 + 仓库外的私有词表 + 私有项目自己的词汇（`ACCEPTKIT_PRIVATE_PROJECTS`，自动收集用例 id、操作 id、包名、白名单值）。
    某个项目特有的证据结构、命名规范、开关名、包名约定，一律经扩展点（`pack.mjs` 的 `dashboardRunExtras` 等、项目配置 `dup.*` / `evidence.cardMarkers` / `hosts`）进来，内核不写死。
    通用能力（比如挂载用例库 `libraries`）留在内核，项目只给自己的内容和叫法。
30. 项目数据、私有扩展、私有词表都在仓库外。
