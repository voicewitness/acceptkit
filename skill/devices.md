# 设备管理标准

验收是「把动作打在一台真机器上」。这份手册管的是：**哪一台、它现在能不能用、这一轮有没有一直打在它身上**。
每一条都对应一类真实发生过的误判，不是风格偏好。

## 一、设备的身份不是它的地址

| | 身份（稳定，用来做键） | 地址（当次有效，用来下命令） |
|---|---|---|
| Android 模拟器 | **AVD 名**（`avd:<名字>`） | adb serial `emulator-<端口>` |
| Android 真机 | serial | serial |
| iOS 模拟器 | UDID | UDID |

Android 模拟器的 serial 里那个端口**按启动顺序分配**：先起来的拿低端口。同一个 AVD 今天是一个号、
明天换个启动顺序就是另一个号；反过来，一个号今天指着这台、明天指着另一台。

**坏掉的样子**（真实发生）：白名单写「某个 serial = 甲 AVD（验收专用）」，某天乙 AVD 先启动占了这个端口。
于是闸门按 serial 放行了「甲」，动作全打在乙上，租约也记在这个 serial 名下 —— **而且从任何一处输出都看不出来**。
serial 相同不等于机器相同。

所以：白名单、租约、run 绑定、证据出处，一律以**身份**为键；serial 每次现查（`adb -s <serial> emu avd name`）。
拿到一个 serial 时先反解身份，再决定要不要动它。

## 二、选设备的顺序：复用 → 启动 → 新建

```
① 已连接 + 已开机 + 没被别人占 + 满足用例要求   → 直接用
② 白名单里有合适的，但没启动                    → 启动它
③ ①②都没有                                     → 才新建，并写下「现有的为什么都不行」
```

- 这个顺序由 `acceptkit device acquire --run R` 执行并留痕：候选有哪些、每台**为什么被淘汰**、最后选了谁，写进 run；复用档直接占上，启动档先启动再占。
  你只核对工具看不出的（登录的账号、页面能不能测），不对就 `device reject`，工具排除它再选下一台。
- **不许凭记忆直接起一台。** 「我记得那台是干这个的」在上面第一条里已经被证伪过。
- 新建是最后一档，不是顺手一档：机器会越开越多，而每一台都带着「它上面装的是谁的包」这个历史包袱。

### 新增设备：用户那边可能还有自己的一步

**纯新增**的设备（之前没在这台 Mac 上验收过，不是重启或复用一台已有的），用户那边常常还要做点什么：
给它的进程配代理规则、装证书、加进某个网络白名单……没做的话流量走错环境，看起来像被测 App 的 bug。
这一步因人因机器而异，**不写在工具里，写在用户自己的配置里**：

- 用户告诉你「装包时什么情况要先卸载」：`acceptkit prefs set devices.reinstall "<他的原话>"`，过装包 / 卸载的闸时会带出来。
- 用户告诉你「新增设备时我还要 …」：`acceptkit prefs set devices.new_device "<他的原话>"`（只存他本机的 `~/.config/acceptkit/config.json`，不进项目、不进工具）。
  之后 `device acquire` 要新建设备时，出的 attention 卡片会把这句带进问题里。
- 那是用户本人的设置，**执行者不改**；等他确认做好了再验收。复用、启动白名单里已有的设备，不需要这一步。

## 三、「空闲」必须是观测出来的，不能是推断出来的

一台设备的状态至少要能回答这五问，缺一问就不叫知道它空不空：

1. 连上了吗（在不在设备列表里）
2. 开机完成了吗（booted，不是只起了进程）
3. 它是哪一台（反解出的身份）
4. 被测 app 在不在跑（有没有进程）
5. 有没有租约、多久没人动它

**查不出来 ⇒ 记「不确定」，不能记「空闲」。** 这是阴性结论那条纪律在设备上的样子：
「我没看到有人在用」和「没有人在用」是两件事。一个平台上这几问答不出来，
就要把这个缺口当结论报出来，而不是默认它空着。

## 四、一次 run 只打一台

claim 之后，这一轮的所有动作 —— 观测、截图、装包、项目自己的 ops —— 目标都必须是 run 绑定的那台。
不等就拒，而不是「以实际跑的为准」。

**坏掉的样子**（真实发生）：一轮 Android 验收的证据里，4 个文件来自甲机、5 个来自乙机，
两台的内存和 GPU 配置还不一样，而 run 里的设备字段是空的 —— 没有任何闸拦下来。
一轮结论横跨两台不同的机器，报告上读不出来，复核的人也读不出来。

**一个需求同一平台也只用一台。** 同一需求的上一轮还占着机器时，`device acquire` 直接接过那台，不另起一台；
上一轮回来接着做时再接回去。确实要第二台（双跑 / 多跑），在新开的运行上 `device acquire --parallel <理由> --why "…"`，acceptkit 核对过才另选：
`capability`（那台给不了这一轮要的能力，工具按能力要求核对）、`case`（用例写了 `parallel_devices.why`）、`owner`（owner 要求，带 `--approved-by` `--quote`）。
理由记进运行的 `parallel_devices`。坏掉的样子：上一轮没收尾占着一台模拟器，下一轮自己又起了一台，新机器上 app 没起、脚本还连着旧机器，断言被误记 blocked。

## 五、占用与释放

关机也只走 acceptkit：自己占着的 `device release <设备> --run R --shutdown`；acceptkit 选设备时启动的、现在没人占着的 `device stop <设备>`（不是 acceptkit 起的不关，可能是用户自己开的）。

- 占用（`device acquire` 自动占，或手动 `claim`）必须记在 run 和 holder 名下：占用记在**哪一轮**名下，谁在用。
- **心跳由每次对这台设备的操作续期**，不是只有闸门续期：续期点越少，租约越容易「人还在用但看起来过期了」。
- 跑完 `release`；收口出报告时自动释放（靠人记得释放 = 迟早不释放）。
- 过期阈值是「这么久没动过就视为没人用」，不是「这么久之后就一定没人用」：
  过期只解除阻挡，不代表可以直接抢 —— 抢要带理由，留痕。
- **占用登记不是唯一真相**：没登记但 app 在跑 = 可能有人没登记就在用，先问，不要直接动。

## 六、设备不是等价的：能力要能被表达

白名单里每台设备要写清它的能力（内存 / GPU / 宿主包 / 登录态 / 一次性机），用例声明它需要什么，
选择按这些标签过滤。

**为什么必须有这一条**（真实发生）：一台内存小、GPU 关闭的模拟器正开着且空闲，
但被测 App 在那种配置上必然卡死（渲染拖垮主线程 → 决策事件为 0 + ANR 循环）。
执行者于是启了第二台大配置的 —— **这个决定是对的**，可是工具里没有任何一处能表达
「这台跑不了这个用例」，也没留下换机的理由。于是对的决定看起来像是乱开机器，
而真正乱开机器的时候也一样看不出来。能力表达不出来，选择就无法复核。

## 七、真机默认不碰

真机有真账号、真数据、真推送。默认只在模拟器上操作；要用真机必须用户明确要求，并记下这句话。

## 命令

日常只用前两条：`next` 出 `device_needed` 卡片时 `device acquire`，核对不对就 `device reject`。其余是看状态和手动兜底。

| 命令 | 它保证什么 |
|---|---|
| `device status` | 白名单 ∪ **实际连接**的全部设备；身份与地址分列；错位、未登记但在跑、租约过期都要显式报出来 |
| `device acquire --run R [--need k=v]` | 平台、宿主、能力要求（用例的 `device_need` 加命令行的）从 run 和用例推出，按第二节的顺序选一台：复用档直接占上，启动档先启动再占；候选、淘汰原因、决策写进 run。返回设备卡片：身份、地址、能力、被测 app 在不在跑、版本。都不行就不占，出 attention 卡片等人加设备 |
| `device reject <身份> --run R --why "…"` | 执行者核对出工具看不出的问题（账号不对、页面不能测）：否决记进 run，释放占用，再选下一台；已经在这台上留了证据的拒绝换机，要重开 run |
| `device pick --platform P [--need k=v]` | 只看候选不占（排查用）：按第二节的顺序给出选择与淘汰原因；带 `--run R` 时写进 run |
| `device claim <身份> --run R --holder H` | 手动占用（acquire 不适用时的兜底）：占用登记 + 心跳；与用例声明的平台不符时拒绝 |
| `device release <身份> --run R` | 只有占用方能释放，不能替别人释放 |
| `gate` | 白名单缺省拒绝 + 必须是本 run 占着的那台；每次放行续租约 |

读到这里还有一句：**规则写在文档里而没有对应的检查，迟早会被绕过**。
上面每一条都应该在工具里有一处强制点；发现只有文档没有检查的，那就是下一个要补的洞。
